# Project failups

## 2026-08-10 — HTTPS отсутствовал после переноса VPS

- Симптом: браузер при открытии `https://complexmedia.ru` показывал разрыв соединения.
- Причина: на новом VPS Nginx слушал только порт 80, сертификата и server block для 443 не было.
- Исправление: выпущен сертификат Let's Encrypt только для `complexmedia.ru`; Nginx настроен на HTTPS и редирект с HTTP.
- Как не повторять: после смены VPS проверять DNS, порты 80/443, `nginx -t` и внешний HTTPS до объявления сайта доступным. `www` проверять отдельно.

## 2026-07-29 — неверная default-ветка

- Симптом: обычный clone дал только `LICENSE`.
- Причина: GitHub default-ветка `main` почти пуста, рабочая история находится в `master`.
- Как не повторять: после clone проверять remote branches и работать от `origin/master`.

## 2026-07-29 — production checkout не чистый

- Симптом: production отличается от GitHub HEAD.
- Причина: deploy-настройки и ассеты менялись прямо на VPS без коммита.
- Как не повторять: перед любой правкой сохранять `git status --short` и `git diff --stat`; не выполнять общий pull/deploy поверх чужого diff.

## 2026-07-29 — секрет в process config

- Симптом: API-ключ находится открытым текстом в `ecosystem.config.js`.
- Причина: ключ добавлен непосредственно в PM2-конфиг.
- Как не повторять: ротировать ключ, хранить его вне Git и передавать процессу через защищённое окружение; не печатать секреты в логах и handoff.

## 2026-07-29 — SMTP relay недоступен

- Симптом: Postfix `mail.cmedia-lead.ru` отвечает с VPS сайта, но отклоняет получателя с `554 Relay access denied`.
- Причина: IP сайта не разрешён для relay, а SMTP credentials не предоставлены; SSH `root`/пароль к mail-серверу отклонены.
- Как не повторять: до deploy формы получить SMTP credentials либо allowlist IP `45.67.32.233`, затем выполнить одно тестовое письмо.
- Решение: выделен непривилегированный SSH-пользователь `complexmedia_forn`; форма использует SSH/sendmail без изменений Postfix и firewall.

## 2026-07-29 — локальная форма возвращала 500

- Симптом: локальный preview показывал «Внутренняя ошибка сервера».
- Причина: API пытался запустить production-only путь `/var/www/complexmedia/scripts/sendmail-via-ssh.sh` на Windows (`ENOENT`).
- Как не повторять: Nodemailer теперь запускает системный `ssh` напрямую и выбирает только путь к ключу/ssh по платформе.

## 2026-07-30 — favicon возвращал 500

- Симптом: `/favicon.ico` падал с `A conflicting public file and page file was found`.
- Причина: один маршрут одновременно создавали `public/favicon.ico` и `src/app/favicon.ico`.
- Как не повторять: для App Router хранить favicon только в `src/app/favicon.ico`; дублирующий файл в `public` удалён.

## 2026-07-30 — staging build Next 16 не принимает внешний symlink

- Симптом: Turbopack завершил staging build с ошибкой `Symlink node_modules is invalid`.
- Причина: staging `node_modules` ссылался за пределы корня сборки.
- Как не повторять: на одном разделе использовать `cp -al` для hardlink-копии
  зависимостей; это не дублирует гигабайт данных и устраивает Turbopack.

## 2026-07-30 — production favicon зависит от Nginx

- Симптом: Next.js на `127.0.0.1:3000` отдавал favicon, но внешний
  `https://complexmedia.ru/favicon.ico` возвращал `404`.
- Причина: Nginx перехватывает расширение `.ico` и ищет файл непосредственно в
  `/var/www/complexmedia/public`.
- Как не повторять: локально не держать дубликат из-за конфликта Next.js 15, но
  при production deploy сохранять отдельный `public/favicon.ico` для Nginx.

## 2026-07-30 — новый public-файл не появился без рестарта

- Симптом: файл подтверждения Яндекс Вебмастера был скопирован в production
  `public`, но standalone-сервер сначала возвращал `404`.
- Причина: запущенный standalone-процесс не подхватил новый public-ассет.
- Как не повторять: после добавления нового production-only public-файла
  перезапускать PM2 и проверять внешний URL; сам файл подтверждения не удалять.

## 2026-07-30 — PowerShell-проверка использовала зарезервированную переменную

- Симптом: локальная HTTP-проверка остановилась на попытке присвоить `$HOME`.
- Причина: для ответа главной страницы было выбрано системное имя переменной.
- Как не повторять: использовать только предметные имена (`$homePage`,
  `$articlesPage`) и не переопределять системные переменные.

## 2026-07-30 — полный HTML-аудит ссылок исчерпал память PowerShell

- Симптом: процесс PowerShell завершился с `OutOfMemoryException`.
- Причина: повторная загрузка и разбор полного dev-HTML/RSC для всех страниц и
  ссылок в одном процессе.
- Как не повторять: проверять маршруты ограниченными агрегатами
  `status/H1/canonical`, а статические ссылки — через `rg`; не удерживать HTML
  всех страниц в памяти.

## 2026-07-30 — прежний пароль web VPS отклонён

- Симптом: SSH к production web VPS отклонил прежний пароль пользователя
  `ubuntu`.
- Причина: актуальные данные доступа неизвестны; mail VPS к этому доступу не
  относится.
- Как не повторять: не перебирать варианты. После двух неудачных попыток
  запросить новый пароль или отдельный SSH-ключ и только затем продолжать
  deploy под lock.

## 2026-08-01 — первичный workflow не должен зависеть от файла на старом сервере

- Симптом: первый автодеплой не смог бы вызвать `scripts/deploy-production.sh`,
  потому что этот файл появляется только в новом коммите.
- Причина: workflow предполагал, что deploy-скрипт уже есть в рабочей копии VPS.
- Как не повторять: сначала читать скрипт из `origin/master` через `git show`,
  затем выполнять его; production-фавикон перед merge сохранять и восстанавливать.

## 2026-08-01 — статистика запросов Яндекса требует расширенного OAuth-права

- Симптом: список сайтов и Метрика отвечают, а query analytics возвращает `403`.
- Причина: токен не содержит `webmaster:verify`, которое API относит к общему
  доступу Вебмастера; это право также позволяет добавлять сайты.
- Как не повторять: заранее сверять права каждого endpoint и отдельно получать
  согласие перед выпуском токена с административно более широким scope.
# 2026-07-30 — OAuth-токены нельзя передавать через браузерные обходы

- Автоматический обмен кода Яндекс OAuth был остановлен политикой безопасности
  браузера на попытке открыть локальную служебную форму.
- Не обходить блокировку и не выводить Client secret, код или токен в команды и
  логи. Использовать `scripts/setup-yandex-oauth.ps1`: он спрашивает значения
  интерактивно и сохраняет токен вне Git с доступом только текущему пользователю.

## 2026-08-10 — Next.js RCE and VPS resource exhaustion

- Симптом: сайт периодически переставал отвечать; перезагрузка временно возвращала его к жизни.
- Причина: на production был Next.js 15.3.1 с критической уязвимостью React Server Components. Через приложение запускались майнер и persistence-процессы от `ubuntu`, поэтому PM2/Next теряли ресурсы.
- Исправление: Next.js обновлён до 15.5.21, выполнены чистые `npm ci` и build, подтверждённые persistence-записи удалены, процессы и файлы помещены в карантин.
- Как не повторять: держать Next.js на поддерживаемой security-версии, не хранить приватные ключи/долгоживущие токены на web VPS без необходимости, после компрометации ротировать секреты и предпочитать rebuild VPS из чистого образа.
