### Шаг B — локальная проверка

Запустить из корня репозитория:

```powershell
git status --short
npx tsc --noEmit
npx eslint src/app src/components src/emails src/seo.ts
git diff --check
npm run build
```

На Windows финальный standalone-шаг может получить `EPERM` на symlink pnpm;
если TypeScript/ESLint и компиляция Next.js прошли, production Linux-сборка
останется обязательной проверкой deploy script. До deploy показать локально
`/services/ai-platform` и изменённые услуги.

### Шаг C — проверить индексацию

- В Search Console открыть Indexing → Pages и URL Inspection. Проверить 3
  `404`, 4 `noindex`, redirect, discovered/crawled not indexed.
- Не снимать намеренный `noindex` с `/seo-dashboard`, demo-страниц кейсов и
  portfolio. Sitemap не должен содержать эти URL.
- Если 404 — старые адреса вне текущего sitemap, оставить их как исторические
  ошибки и не добавлять обратно. Если 404 у актуальной страницы — исправить
  маршрут или ссылку.
- Зафиксировать результат проверки в `project_state.md`.

### Шаг D — commit, deploy и переобход

1. Сверить diff и production-only изменения.
2. Закоммитить весь согласованный пакет в `master`, push в `origin/master`.
3. На `185.65.200.69` запускать deploy только под lock:
   `flock /tmp/complexmedia.deploy.lock bash scripts/deploy-production.sh`.
4. Проверить `systemctl is-active complexmedia`, главную, все новые услуги,
   статьи, API формы и `/sitemap.xml`.
5. В Google Search Console повторно открыть/отправить sitemap и запросить
   переобход приоритетных URL: Harness, шесть услуг и три статьи (учитывать
   дневной лимит запросов).
6. В Яндекс Вебмастере поставить те же URL в переобход; записать статусы задач.
